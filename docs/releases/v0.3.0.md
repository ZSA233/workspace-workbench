# Workspace Workbench v0.3.0

This release changes Agent MCP delivery to a plugin-owned shared HTTP gateway and adds bounded lifecycle diagnostics.

- New interactive Agents, Workspace workers, and Reviewers reuse one loopback HTTP MCP gateway per Workbench plugin process instead of starting one `mcp.mjs` process per session. The gateway is lazy, single-flight, parent-owned, and shuts down with the plugin.
- Existing stdio MCP sessions remain compatible and are identified as legacy sessions; plugin reload does not terminate them.
- MCP routing now receives project, Workspace, role, and session context per request. Workspace creation and status continue to work without Agent identity or handoff context.
- HTTP requests have bounded concurrency and queues, disconnect cancellation, cleanup, and uncertain-write handling. Gateway and stdio lifecycle events include transport, generation, phase, request ID, and cleanup state.
- Added `workspace.workbench.mcp.status` and `workspace.workbench.diagnostics`. Recent diagnostics are redacted, asynchronous, and bounded on disk and in memory.

Validation: TypeScript typecheck, 223 Node tests, HTTP gateway tests, an isolated live Paseo host, and a headless real plugin panel passed. The panel reported no page errors, zero Git commands during 16 idle seconds, and successful plugin/backend recovery.

Existing Agent MCP processes keep their loaded version until the host reconnects them. Reloading the plugin updates the backend and new gateway consumers without interrupting active legacy sessions.
