# Workspace 文件工作台

Workbench 的「文件」Tab 使用当前 Workspace 的真实目录，位于「Git」右侧。「Git」仍是默认页。主工作区使用项目根目录，普通 Workspace 直接使用自己的工作目录。

## 使用

- 桌面采用紧凑文件树：22 px 行高、12 px 文件名字号和 12 px 层级缩进，工具栏与筛选共用一行。触控设备保留较宽松的行高；展开传输队列时也为文件列表保留更多高度。
- 从 Windows 文件管理器把文件或目录拖到树中的目录；空白区域表示当前空间的根目录。悬停目录会展开并显示落点。也可以使用「上传」按钮，Pocket 复用系统文件选择器。
- Ctrl／Command 点击多选，Shift 选择区间；Ctrl／Command+C、X、V 支持跨 Workspace 复制和剪切粘贴。树内拖动移动，Windows Ctrl 拖动复制。方向键、Home、End、Enter、F2 和 Delete 可操作树和文件。
- 右键或触控长按打开操作菜单。删除确认列出空间、路径和目录影响；确认后永久删除。仓库根、Workspace 根、内部元数据受保护。目录上传会复用已有目录；目录复制和 ZIP 会跳过内部元数据，符号链接保留为引用。
- 三个点和右键菜单均显示选中项的名称、相对路径与数量，上传、新建、粘贴的目标目录单独标明。拖回原目录、放到自身或取消拖动不会产生任务记录；Ctrl 复制仍按同名冲突处理。
- 「传输」摘要在 Git、文件和审核 Tab 中持续显示。展开可查看字节、总量、速度、空间、路径和状态，暂停、继续、取消和处理同名冲突。冲突可跳过、保留两份或替换；受保护的目标只提供保留两份与跳过。批量选择只作用于本批同名冲突，传输中途出现的新修改需要重新确认。

没有额外的单文件或整批字节上限。单次请求、分块、并发和内存有边界；磁盘不足或权限变化时，保留任务和已确认进度。移除空间前，需要完成或取消该空间的文件任务。

## 文件树的 Git 状态

显示当前 Workspace 的未提交变动，包含暂存区；它不采用分支与基线的比较结果。文件使用颜色和字母，目录使用颜色和圆点，标记栏与大小列分别对齐。展开箭头、文件夹以及代码、配置、文本、图片和归档使用统一的中性细线图标。

| 状态 | 文件 | 目录汇总 |
| --- | --- | --- |
| 未跟踪／新增 | 绿色 `U`／`A` | 仅有新增、未跟踪时为绿色圆点 |
| 修改／类型变化／删除 | 黄橙色 `M`／`T`／`D` | 黄橙色圆点 |
| 重命名／复制 | 强调色 `R`／`C` | 黄橙色圆点 |
| 合并冲突 | 红色 `!` | 红色圆点，优先级最高 |
| 已忽略 | 文件名和图标灰显，无标记 | 目录自身灰显，不使祖先变色 |
| 干净／仓库范围外 | 普通文字，无标记 | 无圆点 |

忽略项继续显示，可以正常选择、上传、下载和操作。规则由 Git 判断，包含 `.gitignore`、仓库本地排除、全局排除及否定规则；已跟踪文件不会因为命中规则而灰显，实际变动优先于忽略。删除文件不补建虚拟节点，但会计入父目录；重命名同时更新旧、新父目录，共同祖先只计一次。

文件树也识别当前目录中的外层仓库及可见路径上的未登记仓库，仅用于读取状态，不会把它们加入任务或审查范围。目录中混有已跟踪文件时，目录本身可能不被 Git 判为忽略；未跟踪且命中规则的子文件仍灰显。

PC 悬停显示暂存区与工作目录的状态、原路径、目录分类数量或忽略规则来源。触控长按保留原操作菜单，在顶部显示说明，并拦截长按松手产生的尾随点击。

目录先加载，Git 标记随后独立补充。刷新不会清空文件列表，也不改变展开、选择和滚动；失败时保留旧标记并提示「Git 状态待更新」，没有完整结果时显示未知。全局忽略至少每 30 秒重新核验，手动刷新立即核验。旧后端没有 `fileDecorationsProtocol: 1` 时继续使用普通文件树。

## 文件查看与共用高亮

桌面双击文件（或按 Enter），触控点击文件，在主区域打开独立的只读查看页；「返回文件」回到原来的树。文件页保留路径、所属 Workspace、行号、源码搜索、换行、字号、复制和下载，多文件可以切换。它不接管会话消息中的路径，也不提供编辑。

Markdown 默认显示排版，可切换「预览／源码」。标题、列表、表格、引用、链接和代码块通过 `markdown-it` 转换为结构化组件，不执行文档 HTML 或脚本。相对文件、PNG／JPEG／GIF／WebP 图片从文档所在目录解析，经认证 RPC 读取，不能越出 Workspace。单图 4 MiB、当前文档图片总量 8 MiB；排版、节点或代码块超过预览预算时切换到源码，原文件仍可下载。

文件与 Git Diff 共用语言目录、后端 Prism 解析器、文本标记和深浅主题配色。覆盖 Go、JS／TS／JSX／TSX、Python、Java、Kotlin、Swift、C／C++／C#、Rust、Shell、SQL、JSON／JSONC／JSON5、YAML、TOML、INI、Properties、HTML／XML／SVG、CSS／SCSS／Less、Markdown、Dockerfile、Makefile 及常见配置文件名。未知类型按纯文本显示。

Diff 左右两侧分别从冻结提交或固定的文件版本读取完整源码，再把标记映射到补丁与展开的上下文；重命名两侧各用自己的文件名识别语言。跨行注释、字符串和嵌套语法保留上下文，行内修改只增加背景，不切开源码重新解析。标记绑定 Workspace 实例、两侧版本与补丁摘要；主题切换只改配色。旧后端仍可使用原 Diff 与预览入口。

读取每页最多 256 KiB、约 4,000 行；UTF-8、UTF-16 LE／BE 的 BOM、CRLF 和分块字符保持完整，复制保留已加载的原始文本。客户端使用有界窗口，提供后续和上一段，搜索明确标明已加载范围；超长行自动换行并在窗口边界提示续行。超过 2 MiB 的文件使用分段源码模式，二进制显示说明和下载入口。打开或刷新查看页不会创建传输任务，下载沿用先选择保存位置、再开始传输的流程，并核对所查看的版本。

语法解析使用按需启动的独立 Worker：相同实例、固定源码、语言和渲染模式共享进行中的解析，每个订阅者独立取消；一次一个作业、最多 24 个不同的等待作业、3 秒超时、128 MiB 堆边界，闲置 30 秒退出。后端标记缓存最多 32 项／8 MiB；客户端查看快照最多 8 项／8 MiB。缓存按主机、项目、Workspace 实例和版本核对；关闭、移除空间或切换页面时使迟到结果失效。查看页前台定期只核对文件元数据，文件变化时保留原快照并提示刷新，不触发仓库 Git 扫描。

## 恢复与保存

上传以服务端落盘并写入日志后的字节数计进度。更换 Tab、切换空间、重连和后端重启会保留任务 ID 与原目标。客户端重新打开后，未保留读取权限的文件需要重新选择；名称、大小、时间和已传分块会校验。

点击下载时先选择保存位置，再开始远程准备和传输；取消选择不会创建任务。下载按固定版本分块保存到浏览器的 OPFS，完成后自动流式写入已选择的目标，最终写入流成功关闭后才确认完成。每个暂存块带校验信息；取消最终保存可以保留下载暂存并再次选择保存位置。刷新页面后丢失的保存权限需要在队列中重新选择。多选超过单次请求预算时，分批确认选中路径后生成同一个 ZIP，始终只选择一次保存位置。未收齐选择时不会生成部分归档；路径批次支持确认丢失后的核对与重放。存储不可用时直接流式保存，这次保存不提供跨刷新本机续传。浏览器需要安全上下文并支持相应存储能力才能恢复本机暂存。

缺少文件保存接口时，下载会自动使用已有宿主的下载 token 交给浏览器。页面必须通过同源 `/api/status` 核对宿主身份；状态显示「交由浏览器下载」，保存结果由浏览器管理，不显示插件无法确认的精确进度或完成状态。反向代理、集中部署的网页或受限制的浏览器若无法通过身份核对，会保留任务并说明原因。

Pocket 通过独立、仅允许可信主页面调用的桥打开 Android 系统保存选择器，逐块写入所选文档。Pocket 0.1.7 的保存目标分别管理，系统选择器依次展示；选择其他目标不会阻塞已有文件写入，选定 URI 后到真正写入时才打开输出流。关闭或取消只影响对应文件，零字节文件也必须成功关闭。旧 Pocket 由插件顺序等待可用保存会话。前台断网可以继续；本版没有新增后台常驻服务。Activity／进程重建中断了最终保存时，需要重新选择保存位置；系统提供者对未关闭文档的处理取决于提供者。插件不会把未关闭的保存流记为完成。

## 存储和清理

- Git 与目录派生观察继续使用每项目的 `observer-node-cache.json`，默认最多 500 条、32 MiB。条目记录 Workspace 实例与仓库归属；完整有效的空间清单用于回收无归属条目，共享仓库仍有空间使用时保留。
- 成功移除或删除空间后，清理对应观察、目录、提交时间索引和客户端状态，并使迟到请求失效。失败或不完整的清单不会触发空间清理。文件系统删除失败时保留恢复现场与运行历史。
- 独立任务日志在 `<stateRoot>/file-transfers/tasks.sqlite3`；确认分块与任务状态持久化，内容保存在 `.part`。最终提交使用目标文件系统中的 `.workbench-transfer-*` 暂存，并在相关仓库的本地 `info/exclude` 加入该保留名称模式。用户已有忽略规则会保留。
- 未完成、暂停、冲突和失败任务不按普通缓存淘汰。完成或取消后清理临时内容、释放分块日志；终态元数据按七天与最近 1,000 条保留。正在恢复或清理失败的内容保留所有权记录，清理失败可在队列重试。
- 交给浏览器的临时快照会延迟回收，为宿主 HTTP 保存留出时间。存储信息菜单显示派生缓存和远程传输临时内容的逻辑大小。进程租约数据库和用户运行时历史不在本次清理范围。

## 实现和验证入口

`server/backend/files.ts` 负责读取和目录观察，`file-roots.ts` 负责实例、路径与保护边界，`file-tasks.ts` 负责任务与提交，`file-journal.ts`、`file-cleanup.ts`、`file-io.ts` 分别负责日志、清理与有界 I/O。RPC 走已有认证连接，512 KiB 分块，最多两个文件传输、最多四个分块请求的预算；下载每个文件最多预读两个分块，按源偏移核验并消费，消费速度控制后续请求。后端声明 `fileReadWindowProtocol: 1` 时，读取请求可以捎带已经持久暂存的连续确认偏移；重复、迟到确认不会回退进度。最后一块仍独立确认，最终保存流成功关闭后才完成任务；旧后端继续逐块读／确认。

目录和多选由 `yazl` 流式生成 ZIP64；已有压缩格式不再压缩。纯准备进度每 250 ms 或累计 128 项合并落盘，提交、控制和上传分块确认仍立即持久化。文件列表按需展开、分页加载并虚拟化，刷新失败保留内容、选择和位置。队列使用独立外部状态订阅，普通进度最多每 200 ms 通知一次，状态变化立即通知。隐藏面板停止闲置查询和界面订阅，正在推进的任务继续运行；返回时保留缓存并合并校验。

支持 `directoryListingProtocol: 2` 的后端先返回首批目录页，再后台准备全目录的“目录优先、名称排序”。名字索引计入现有派生缓存的容量与归属，且不持久保存；超出索引预算时逐页使用有界排序窗口。游标绑定目录版本和顺序，操作或滚动期间保持已有顺序，回到顶部且没有选择、菜单和手势时应用新顺序。

小型删除及上传提交最多短等 250 ms 获取已完成结果；长操作继续显示任务。已确认变更随任务返回，立即移除已删除条目，并合并刷新受影响目录；新鲜读取等待权威列表，旧请求不能把已删除内容重新写回。后台轮询仍用于外部文件变化及断线恢复。

`file-decorations.ts` 查询 Git 装饰，`repository-status.ts` 在现有有界缓存内共享原始 XY 状态；Git 页和文件树共用这些快照，保留暂存后再次修改及同一路径的多条状态。`decorations` RPC 每批最多 200 个路径、60 KiB 路径载荷，客户端再按可见范围和字节预算分批。忽略检查只处理请求中的路径，通过有界 NUL 标准输入调用 Git，不遍历被忽略目录。Git 统计补齐、传输日志和内部暂存写入不触发文件树的状态扫描。

```sh
npm --prefix paseo-plugin run typecheck
npm --prefix paseo-plugin test
node paseo-plugin/scripts/verify-files-ui.mjs
node paseo-plugin/scripts/verify-files-git-ui.mjs
node --experimental-strip-types --max-old-space-size=192 paseo-plugin/scripts/verify-files-large.mjs
```

UI 脚本加载实际插件，并使用隔离的 Paseo home、项目注册表和临时 Git 仓库。Chromium 测试的导出目标是实际 OPFS 文件句柄；它验证流式提交，不代替 Windows 原生保存选择器验收。大文件脚本验证超过 4 GiB 的文件、归档、完整性与内存；它是 Node 文件服务实测，不是 Windows 客户端吞吐测试。

具体证据和平台待验收项见仓库的 `docs/workspace-files-verification.md`。
