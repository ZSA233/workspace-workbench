# 生产覆盖与未提交状态审查

2026-11-27，补查 v0.13.12 之后同类误判与标题笔号更新触发。

原核对优先比较生产／工作区文件对象；文件不同则查需求补丁在生产文本中的唯一连续上下文，无法确认也会使整个需求显示未上线。v0.13.12 补上“提交已包含于生产＋整个提交文件按顺序保留”，解决币商中心的追加配置，但生产改写其他旧内容、squash 或 cherry-pick 时仍可能不满足该补充证明。

本轮使用按实际修改位置的证明替代整文件顺序保留的补充检查，将未修改的上下文与需求变化分开，依据当前生产文件映射核对。需求新行须完整、唯一保留；碰到需求行改写／删除、重复片段、删除边界变化、恢复旧值或有界证据不足时拒绝此证明。不借助模型推断上线，不仅凭可达性标绿。额外回归验证生产在新值后恢复旧值、又插入其他内容时，即使整个工作区文本仍按顺序保留，也不能据此确认已上线。

| 验证场景 | 期望 |
|---|---|
| 普通 merge、squash、cherry-pick 后修改周围内容 | 保留上线结论 |
| 周围独立增加、替换、删除旧内容 | 保留需求修改的位置证据 |
| 回滚或部分删除需求修改 | 不能标绿 |
| 重复／移动片段、旧值紧邻新值恢复、删除边界重叠 | 不据此证明全部上线 |
| 二进制、无效文本、缺行尾标记、截断补丁 | 不据此证明全部上线 |

笔号问题另行实查：关系迁移与退款关联的五仓库中，读取时 `halh` 有三份协议文档修改与一份未跟踪文档，另外四仓库干净，所以该时刻笔号有实际依据，未修改这些用户文件。但旧实现只在进入会话页、刷新或会话回合结束时检查，Git 状态变化没有直接唤醒标题维护，且资料变化时模型等待时间可能阻塞符号更新。

新增只对已授权会话的轻量来源版本订阅，默认每 5 秒读取已有观察版本标记，变化后沿用默认 30 秒 debounce；未变化不扫描提交，不发模型请求。标题符号以当前 Git 证据维护，正文沿用已接受标题；摘要预览不因此被伪装成已重新分析。关闭、外部改名、配置版本与不确定写入保护继续执行。插件启动只恢复原有会话授权，不做新授权或项目批量改名。

生产覆盖测试在修改前复现三种合入方式的相同误判，修改后通过，随后回滚需求依然不能标绿。币商中心八仓库使用最终代码只读核对仍为已上线，约 684 毫秒。

`make check` 最终通过版本、TypeScript 与全部 1,042 项 Node 测试；生产文本、真实 Git 覆盖与会话流程相关测试 59 项通过，桥接缓存／控制请求相关 7 项通过。并发 UI 验证期间有一次已有文件监听恢复用例超时；该用例随后单独与完整套件均通过，未放宽等待预算或修改断言。

实际隔离 PASEO UI 验证 27 项通过、页面异常为零。在真实临时 Git 中保持需求提交已上线，将界面切到 Git、卸载会话 Tab，依次恢复干净、创建未跟踪文件、删除该文件；原生标题笔号三次自动跟随变化，已上线状态和已接受正文保留，旧预览仍显示过期，没有新模型请求。三次更新合计约 11.982 秒；这项测试将 debounce 调成 0 秒、模型等待时间调成 300 秒，以检验后台观察与模型等待独立，默认生产设置仍是 30 秒 debounce。模型为 HTTP 夹具，Git、隔离宿主和原生标题是真实对象；不作为真实本地模型质量证据。

自动内容证明仍有边界：需求实现被重构或改名、与其他变化重叠、缺少基线／生产引用或超过有界证据时，不能保证仅靠 Git 文本自动确认。保留诊断证据，不用相同提交数量、相似文案或模型判断弥补缺口。

最终版本的 `verify-live.mjs` 独立实际宿主验证通过，使用隔离 home 和项目注册表，宿主连接、后台工作进程与卸载回收核对正常。版本一致性、发布 tag 检查及本地插件打包通过。
