# 摘要、生产状态与标题维护

Workbench 的“摘要”和“设置”Tab 属于插件页面。设置首页直接展示模型地址、自动整理开关和全部配置入口；详细页面采用单列表单与折叠组，适合窄 Explorer 面板。Diff 字号、换行与并排显示留在 Diff 工具栏。Paseo 设置中也可直接进入 Workbench 设置，无需先选择 Workspace。原来的运行时、审核、存储、仓库与扩展设置入口会打开对应页面。分类切换保留草稿，切换编辑项目或作用范围时可保存、放弃或继续编辑。编辑项目固定，不跟随会话焦点改变。

## 连接本地模型

在“设置 → 配置地址与模型”中填写连接名称、Chat Completions 地址、模型 ID 和可选 Bearer Token。地址通常以 `/v1` 结尾。默认选中当前使用的连接。支持多个连接；认证单独保存为主机私有文件，不返回客户端，也不写入项目配置或模型输入。

默认上下文预算 16K tokens、输出上限 2K tokens、120 秒超时。采用保守字节预算并明确显示截断；预算可在连接中修改。模型并发默认 1，在主机默认规则中可调整为 1–4。工作区整理和测试共享同一有界队列。Sushi 必须已有指定模型处于 loaded/ready；Workbench 不加载、切换模型或自动改用其他服务。

“检测连接”只读模型目录。“不写标题的生成测试”以后台任务运行，可取消，展示实际提示词、输入及来源、截断、输出、耗时与用量。历史分析的运行记录也可查看这些材料。超时、无效 JSON、输出不完整或虚构引用均不会成为有效分析结果。

## 历史内容先预览

1. 进入“摘要”，在项目内选择会话或工作区；批量处理进入“设置 → 历史预览与标题维护”。
2. 核对“本次分析材料”，点击“生成摘要与标题预览”。可选择是否包含会话讨论。进度记录当前对象、阶段和真实模型请求，支持取消和重试。
3. 核对原题、建议标题、事项和生产证据。材料、模型实际输入与输出按需展开。没有明确关联的工作区可以生成摘要，不能据此猜测会话归属。
4. 点击“核对并应用标题”，在独立确认框中确认。批量预览每批最多 200 个工作区，按选定顺序处理；取消或切换项目后不继续启动后续批次。继续自动维护还需开启总开关。

安装、升级和首次启用都不会接管历史标题。关联只来自创建者记录或经过身份核对的执行绑定，不按目录相同猜测会话。已经分析过的历史预览可在焦点或刷新时更新生产证据。

## 维护未来内容

启用“自动维护未来内容”后记录时间边界。明确关联的新条目可全部纳入、只纳入指定 Workspace/Paseo ID，或使用排除名单。创建 Workspace 时可以填写一句话目标与需求/Bug/改进/讨论类型；原来的创建接口仍然可用。

默认事件合并等待 30 秒，同一对象自动模型分析至少间隔 5 分钟。面板进入前台、焦点恢复或普通刷新检查版本与缓存；创建和会话回合结束也会标记变化。没有新材料不重复推理。会话按公开用户/助手文本增量读取，工具输出不进入摘要；长消息保留位置，部分覆盖会明确标示。

界面的轻量状态查询只读取任务记录。生产核验、关联检查与模型分析分别记录，不以扫描数量冒充生成进度；切换设置分类不启动任务。已读取的空材料、缓存命中及未配置连接有独立结果，模型校验失败不显示为有效预览。运行记录保留当时的模型 ID 和地址，历史测试也可重新打开查看。

正式短标题按代表 Workspace 保存。后续摘要、模型或提示词变化不会同义改写正文；“重新生成标题建议”提供显式预览。代表对象按未上线优先、同组最近实质活动选择；全部上线后取最新。获取引用、观察时间和模型运行不会改变实质活动排序。

每次写入前重新核对材料、配置、对象身份和当前 Paseo 标题。发现当前标题不同于上次写入值时，保留外部编辑并暂停；不会猜测是用户、宿主还是其他插件改名。可恢复维护、仅更新符号，或排除。仅更新符号会保留现有正文。恢复原标题同样检查当前值，不能覆盖后来的改名。结果未确认的写入保留日志，不自动重发。

## 生产符号

| 默认符号 | 含义 |
| --- | --- |
| ✓ | 全部代码已被所选生产引用当前内容覆盖 |
| ◐ | 部分上线，或还有新讨论目标 |
| ○ | 有未上线修改 |
| ? | 基线、对象、获取结果或内容证据不足 |
| · | 讨论中，尚无自身代码修改 |

各仓库在“生产与上线”配置生产分支，兼容已有 Compare 生产分支值；未配置时依次选择存在的 `origin/main`、`origin/master`。也可指定其他本地或远端分支。默认获取焦点/刷新时，远端生产引用超过 15 分钟才获取一次；强制获取按钮绕过该缓存。获取沿用有日志、有界的 Git 执行路径，不合并或切分支。

判断使用冻结创建基线、Workspace 自身提交、当前工作区变化和生产内容。相同 blob、等价补丁的当前内容核验可识别合并、squash 与 cherry-pick；可达性、提交数量和 patch-id 都不能单独证明全部上线。回滚、重叠/模糊文本、缺失对象、旧记录无基线等情况保守显示待核实。多仓库分别判断后汇总。有未提交修改时不会全部上线。事项的完成勾选与代码覆盖独立；模型的完成主张显示待确认，人工修正优先保留。

符号可改成 emoji 或短文字。插件内部显示彩色状态；原生列表使用已验证的标题字符接口。额外原生行徽标尚未开放，不能把插件页面里的色块理解为原生列表红点。

## 数据与边界

连接、秘密和模型测试保存在当前 Paseo home 的 `workspace-workbench/organizer`。项目整理记录位于项目 state 的 `organizer/hosts/<主机身份摘要>`，工作区按实例身份区分，Paseo 目标按对象 ID 区分。保留原标题、修改历史、会话断点与运行记录；进行中的整理任务和模型测试在重载后标为中断，由用户核验后继续。

Workspace ID、分支、目录和 schema-v1 记录不因标题维护改变；归档仍由用户操作。整理事项属于 Workbench，与外部 AI Assistant 档案话题、发现、采集和模型策略独立。权限预设、Reviewer、恢复和旧话题接口继续使用原有服务与存储。

验证命令：`npm run typecheck`、`npm test`、`npm run test:organizer-ui`。最后一项运行实际隔离 Paseo 和 Playwright，使用临时注册表、Git 仓库、协议会话及 HTTP 模型夹具；不会更新正常安装或派发真实业务 Agent。
