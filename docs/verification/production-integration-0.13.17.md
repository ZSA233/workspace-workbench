# 已合入生产分支仍全部标红的核对

2026-11-28，核对正常实例中当前会话明确关联的 21 个 Workspace。Git 图显示其中 20 个工作区的所有提交已在本地 `origin/main`；剩余 DWS 工作区仅一个旧嵌入式 Web bundle 更新提交的编号不在主线，相关源码已集成，当前主线具有另一套完整、更新的模块入口及构建资源。两个仓库的 `git ls-remote` 与本地所选引用一致。

旧结果包含以下独立问题：

- 一次远端 fetch 超时被共享为所有同源仓库的“引用不可用”，即使本地生产 SHA 与工作区 SHA 相同也会标红。fetch 总期限为 30 秒，但使用普通 Git 的 3 秒命令时限；失败备忘又压住之后已成功的收据。
- 文件明细达到 160 项时，完全相同的生产树也因未扫描剩余文件而失去已上线结论。
- 在主线继续迭代后，旧版本号、旧生成 bundle、函数重构或拆分不再与旧工作区逐字相同，旧内容比对将这些正常演进视作未上线。
- 无独立提交的基线／同步工作区与实际代码改动混合汇总，导致已有代码全部上线仍显示未上线。

修复分别记录生产树一致、提交集成、源码集成及替代构建、等价补丁和回退依据。已集成后不要求永久保留旧文件内容；明确撤销本工作区自身提交、整个原实现被恢复或整体反向修改仍核对当前内容。上游被合入的其他提交发生回退，不扩张成本工作区的回退。未集成源码与仅有类似文件名的手写资源均不能被构建替换规则忽略。模块入口和替代资源必须为正常 Git blob，缺失资源与符号链接不作为完整构建证据。

获取失败仅另附远端刷新提示，保留确知的本地生产提交结论；没有本地引用对象则不提升为已上线。成功收据可恢复失败备忘，失败期间有重试退避。同源 worktree 获取引用后，后续读取使用各自读前、读后的新版本，避免使用旧全局版本导致证明全部失效。变更不调整模型调用间隔或新增模型触发。

同一真实数据的候选算法只读核对结果：18 个有独立改动的 Workspace（其中一个含两个仓库，共 19 份仓库证据）已上线；3 个无独立提交的 Workspace 保留“暂无改动”，不声称其讨论任务已经完成。未改 Workspace ID、分支、创建基线、关联、原有配置或归档状态。

测试覆盖正常主线演进、文件移动／拆分、同树超明细上限、未应用需求的 ours-only merge、显式回退及重新应用、上游无关回退、无源码合入的生成 bundle、缺失／符号链接构建资源、squash／cherry-pick、已有覆盖旁的本地改动和引用失败恢复。原先“文件直接消失”的回退夹具改为实际 `git revert`，与普通重构退役区分；回退断言仍保留。


最终 `make check` 通过 TypeScript、版本一致性和完整 1,074 项 Node 测试。受影响 91 项检查通过；小文件上传的既有前台完成时限断言曾在并发全量中一次失败，该文件独立 20 项与最终全量均通过，未放宽断言。实际隔离 PASEO 界面回归通过 33 项（含无提交工作区的中性标记），浏览器异常为零；独立隔离宿主加载、重连、进程所有权和卸载检查通过。tag 检查及插件打包通过。界面模型使用 HTTP 夹具，真实仓库 Git 审计与宿主证据分别记录。
