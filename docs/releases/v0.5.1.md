# v0.5.1

- Fix the native recovery-state initialization that could fail with
  `Cannot read property 'prototype' of undefined` and prevent Workbench from
  loading. Recovery state now uses a function factory rather than a class.
- Configure diagnostics before client registration and retain the failing stage,
  stack and client generation through the existing diagnostic interface.
- Register the core Workbench separately from optional recovery controls. Roll
  back partial setup and clean up subscriptions, timers and status controls on
  unload, even when another cleanup fails.
- Load the recovery screen only when opened. Preserve existing recovery settings,
  backend authorization and continuation-message behavior.

Validation: TypeScript checks and all 619 tests passed locally. Hermes reproduced
the former construction failure and verified the fixed production state and
compiled client entry, including repeated registration and cleanup without DOM
globals. These engine tests substitute host APIs and schemas; they are not an
Android device UI test.

An isolated actual Paseo host passed lifecycle and reconnect verification.
Playwright verified recovery settings, saving and reloading, Workbench browsing
and opening a working-tree Diff with no page errors. Android device appearance,
touch interaction and reconnect acceptance remain unverified.
