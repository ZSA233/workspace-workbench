# 0.14.0

统一整理功能的大模型入口，减少无业务变化时的读取和重复生成。Git 原有全工作区预热、范围、频率和调度保持不变。

- 自动模型处理只面向已开启维护的会话及其明确关联的工作区；关闭开关后，普通进入不再生成摘要或标题。首次开启可以建立必要摘要，之后只由新的自身提交触发。
- 分开保存提交摘要、手动预览、生产覆盖及未提交状态。编辑、暂存、刷新、上游合入、生产引用更新、纯消息变化和旧历史未读不触发生成；状态变化只更新符号。未确认的手动预览不会被后台写入。
- 复用既有 Git 状态和活动事实，用实例、冻结基线和自身提交识别业务内容。忽略观察租约和不相关配置版本，稳定缓存不重复深读。
- “最新工作优先”先处理最新一批并写入标题，其余摘要分批补充。每批最多四个工作区，默认单并发；手动预览、重试和首次开启优先，支持取消、共享请求及变化合并。
- 同一输入超时或网络失败持久退避 5／15 分钟，三次后暂停；输出校验失败不原样自动重发。模型未就绪、限流及连接异常统一冷却，不切换模型，不设置每小时硬上限。
- 旧历史通过“查看依据 → 补充历史”手动处理一批并保存断点，不自动补读或改标题。
- 原有“模型设置”弹窗增加折叠的“Workbench 队列与用量”，可配置主机并发 1—4、查看和取消任务、查看实际 POST 次数。保存 30 天小时统计和最近 1,000 次请求元数据，详细输入输出仍有限保留。
- 过程弹窗记录 Git 核对、材料读取、模型排队、连接、请求、校验和写入耗时。升级保留秘密、开启状态、schema-v1、关联及标题历史，不批量改名或归档。
