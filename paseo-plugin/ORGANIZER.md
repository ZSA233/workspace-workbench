# 会话、工作区摘要与标题维护

在当前 PASEO 会话中打开 Workbench，选择“会话”Tab，即可查看这个会话明确关联的 Workspace。每行显示工作内容、原工作区名称、Git 最新提交时间、短摘要和生产状态。点击整行，会选中该工作区并进入 Git。

切换 PASEO 会话只更新“会话”页资料；手动选择的 Workbench 工作区和当前 Tab 按主机、项目记忆。手动切换顶部工作区不会改变会话页的关联范围。自动关联来自创建者记录和经过身份核对的执行绑定，不按目录相同猜测。已确认的关联按主机、项目、会话和工作区实例保存，不依赖 Agent 始终处于活动状态。无会话上下文时不显示全项目资料。

## 手动关联工作区

在会话页点击“关联工作区”，默认显示顶部当前选中的工作区和当前 PASEO 会话，点击“确认关联”即可添加；已有的其他关联保留。当前工作区已经关联时显示“已关联”。点击“选择其他工作区”，可搜索、多选并“保存关联”。主工作区或已不可用的选择直接进入项目工作区列表。旧工作区没有创建者记录时，也可这样补充。取消勾选可以移除关联；自动识别的关联被取消后，普通刷新不会再次加入。取消弹窗不保存选择。

关联仅用于这个会话的工作区列表、摘要和标题取材，不改创建者、执行 Agent、交接或审核范围，不切换顶部工作区。手动修改范围会停止当前整理、使旧预览失效，并关闭已开启的标题维护；重新打开开关即可按新范围在后台维护，也可先预览。工作区删除后以同一 ID 重建时，不继承旧实例的关联。归档或不可用的记录保留关联历史。

## 配置模型

在原有 `⋯` 菜单打开“模型设置”。接口地址、模型 ID 和可选认证直接展示；连接保存在主机，项目选择所用连接及命名规则。认证保存在私有文件，不返回客户端，不送入模型输入。“检测连接”测试当前草稿，不必先保存。

命名偏好有“最新工作优先”“整体需求概括”和“自定义”。默认根据 Git 页同一最新提交时间选择近期工作，综合所有关联 Workspace 及增量会话内容命名；不固定未上线优先，也不强制保留原题字样。命名提示词和标题长度直接展示；上下文预算、输出上限和超时在高级设置中。

默认上下文 16K tokens、输出 2K tokens、120 秒超时、模型单并发。Sushi 的指定模型必须已经 loaded/ready；Workbench 不加载或切换模型，不自动改用其他服务。

扩展、项目存储、运行时、审核、仓库范围和恢复沿用原来的入口、弹窗、服务及存储。没有统一设置首页或设置 Tab；Diff 显示选项留在 Diff 工具栏。

## 查看摘要与维护标题

- 打开会话页立即显示缓存；仅更新这个会话有新材料的工作区。模型处理每批最多 4 个工作区，分别返回短摘要，最后综合为独立会话标题建议。
- 没有独立提交材料时，仍可进入工作区，暂不生成摘要。已有人工说明优先保留。空基线不代表新的未上线需求；有明确目标的新讨论仍单独保留状态。
- 开启“自动更新标题”立即保存当前会话的授权，在后台核对和更新，不必先等待预览；已有有效建议直接复用，正在进行的整理复用原任务。排队或生成期间也可以立即关闭，关闭后旧任务不能再写标题。
- “预览标题”是可选操作，不写标题；仍可在预览里“应用并开启”。关闭维护保留当前标题，离开会话页不取消已开启的后台维护。
- 开关只控制当前会话。旧项目级 enabled、范围和名单仍保存在记录中，但不再授权自动纳入。升级不会自动接管未开启的会话。
- 有变化才调用模型。会话回合结束、Workspace 创建和面板进入前台触发有界检查；默认合并等待 30 秒，自动分析最少间隔 5 分钟。生产状态变化可以只更新符号，不需要重新生成正文。
- 已接受的同义标题保持稳定。模型、提示词或命名模式改变后，重新打开开关即授权按新配置后台维护，也可先预览再应用。
- 预览后资料或命名配置改变时，建议标为过期并禁用应用，可直接“刷新预览”。内容相同的文件触碰不会失效。确认只使用本次预览编号，不自动重试未知结果的标题写入。

标题区显示当前阶段、具体对象和实际耗时：读取提交与差异、核对生产分支、读取会话记录、生成标题／摘要、校验结果。完成后直接展示建议标题，并区分摘要更新、缓存复用和模型未调用。新关联会话可以复用工作区摘要并单独生成会话标题。

点击“查看过程”，可在本次任务中查看仓库、提交、差异及改动说明数量、会话页数与公开片段、模型请求次数和输出校验情况；处理记录、实际输入、输出和提示词默认折叠。这里也可取消当前任务；失败保留已有内容，并可重试。预览弹窗的“查看依据”保留原有来源核对。短来源编号保存可逆映射，校验后才转回实际来源 ID。模型额外返回的已知、未请求工作区摘要被舍弃，未知身份、缺失的请求结果和虚构来源仍会拦截。

模型优先读取目标、交接、自身提交、改动说明及必要差异；发布记录、主分支合入和生成产物降低优先级。长会话只读取公开用户/助手文本，分页保留断点，工具输出不进入摘要。部分覆盖如实显示，未读取的长消息后半段不会被确认已读。缓存预览先核对消息尾部版本，不为了打开预览再次归纳尚未读完的旧历史。

写入前重新核对全部关联、材料、公开消息版本、配置与宿主对象。外部改名暂停维护；结果未知的写入保留日志，不自动重发。重新读取预览并显式确认后，才允许人工重试。取消、配置改变、停用或插件重载后的过期模型结果不能写标题。

## 生产状态

需求主状态只分已上线／未上线：已提交的整个需求全部确认进入生产分支后才标记已上线；仍有任何已提交需求改动未上线，或尚不能确认完整覆盖，就保持未上线。不会按已覆盖文件、仓库或 Workspace 的比例标为“部分上线”。

在 `⋯ → 模型设置 → 标题样式` 选择简洁符号、彩色 emoji 或短文字，两个主状态可单独自定义。已有其他符号配置保留兼容，不再作为标题主状态使用。设置按项目保存，取消编辑不写入；保存后在会话页预览确认。

已提交内容全部上线、但还有本地未提交修改时，保留已上线并附 `✎`，页面同时显示“有未提交改动”。新目标只有未提交内容、尚无独立提交时保持未上线。该提示与标题正文分开保存；只改符号且正文版本可核对时复用正文，不重复请求模型。

状态由 Git 证据计算，与模型描述分开。插件内部使用现有主题的状态颜色，原生列表只写标题字符及 emoji，不控制宿主标题字体颜色。命名提示词只指导正文；可用“业务对象＋处理的问题，避免提交编号、版本号与底层实现细节”等规则。实际输入及提示词位于会话“查看过程／查看依据”中的模型记录。

生产分支沿用 Compare 已有配置；可在 Git 比较中选择起点，再于“比较设置”选择“将起点保存为生产分支”。无配置时依次采用存在的 `origin/main`、`origin/master`。远端引用默认缓存 15 分钟，获取复用原有有日志、有界的 Git 路径，不合并、不切分支。获取失败、基线缺失、回滚和模糊内容保守显示待核实；可达性或 patch-id 不单独证明已上线。会话页“上线依据”列出每仓库使用的引用与判断原因，模型成功不代表代码已上线。

模型材料截断与上线覆盖分别记录。覆盖数量只作为诊断依据；已覆盖一部分不代表整个需求上线。提交的需求改动全部确认覆盖才显示已上线，其他情况保持未上线，未核实原因放在仓库依据里。自身历史与覆盖路径有固定上限，超限保留原因，不放宽进程和输出边界。

## 数据与验证

模型连接和秘密保存在当前 Paseo home 的 `workspace-workbench/organizer`。整理记录在项目 state 的 `organizer/hosts/<主机身份摘要>`。新短摘要、会话标题建议和维护状态为附加字段；保留 schema-v1、未知字段、原标题、修改历史及旧摘要。Workspace ID、分支和目录不改变，归档由用户操作，与外部档案话题的采集和发现策略独立。

运行 `npm run typecheck`、`npm test`、`npm run test:organizer-ui`。界面验证使用实际隔离 PASEO、临时注册表和真实临时 Git，协议 Agent 与 HTTP 模型夹具；真实 Sushi/YUVA 取材试验另记，不将夹具当成真实模型证据，不更新正常安装或派发业务 Agent 来测试。
