# 0.13.17

修复已合入生产分支的旧工作区被全部标为未上线的问题。

- 区分“提交已进入所选生产分支”和“当前文件仍与旧工作区逐字相同”。后续主线重构、版本更新、文件拆分和构建更新不再撤销已确认的合入状态。
- 相同生产树直接提供完整证据，不因明细扫描文件数上限而误判；明确撤销提交、整体反向修改和恢复原实现的证据继续检查，未合入的源码仍须验证当前等价补丁。
- 仅剩生成的 Web bundle 提交时，核对源码提交已合入及双方模块入口、生产替代资源完整性。不能仅凭文件名或提交标题忽略改动。
- 远端获取失败单独提示，保留已有本地生产提交的判断；恢复成功后清除旧失败缓存。Git fetch 使用已有 30 秒操作时限，不再被普通 3 秒 Git 读取时限截断。
- 没有独立提交的工作区显示中性“暂无改动”，不把其他已上线改动拖成未上线。
- 每次读取记录自身的源版本，避免先前 fetch 更新共享引用后令后续工作区的缓存证明失效。

上线符号继续由 Git 证据决定，不依赖模型生成；标题正文、模型设置、关联和手动归档行为保持原有规则。
