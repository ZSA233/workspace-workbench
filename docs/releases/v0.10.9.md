# 0.10.9

修复话题图片的原件已经归档，页面仍一直显示“等待原件”的问题。读取话题时核对相同附件 ID 的当前归档状态；仅在展开的前台话题或上下文窗口仍有待就绪附件时，每 10 秒轻量刷新，全部就绪后停止。手动刷新也会更新已展开详情。不会启动采集或下载任务，不改变历史消息、版本及已选材料，也不会自动选中新就绪附件。

项目关联 Workbench 后，Paseo 普通交互会话默认自动获得独立的 MCP 身份，无需补配 `agent.provider`、桥接脚本或 Token；仍保留 `agent.bridge.autoInject: false` 的显式关闭选项。支持运行时 MCP 注入的宿主会在已有会话下一轮开始时补齐缺失身份，保留原会话 ID、原生历史和模式，不中断正在执行的一轮。运行时注入使用独立名称，兼容旧会话已保存的 MCP 配置。

连接检查单独报告项目和身份是否随请求传入，不再把服务连通等同于身份可用。缺少会话 Token 的请求不会派发，错误不再建议反复检查连接重试；备注作者验证、跨项目隔离及 Worker／Reviewer 边界保持有效。失败的备注不会自动重放。

验证：TypeScript 检查及 902 项 Node 测试通过；最终 MCP 调整的 26 项相关测试通过。真实隔离 Paseo 宿主配合本地 Codex 协议夹具验证老会话自动恢复、连续两次插件更新、两个新项目零桥接配置、实际 HTTP MCP 备注读写和越权拒绝，不调用模型、不向用户项目写入测试备注。实际浏览器验证待就绪图片约 10 秒后显示、就绪后停止轮询、手动刷新详情及选择保持；深色及 390px 面板无页面脚本错误。真实归档服务只读复核确认截图对应的三个原件已就绪，历史正文、版本和附件 ID 未改变。
