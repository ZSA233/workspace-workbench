# 跨端附件历史：原因与维护边界

## 已核实的历史

Pocket 0.1.8/0.1.9 的图片兼容代码属于 APK：修复系统选图返回、MIME
识别和输入框附件。代码随 APK 发布，不修改用户安装的 Paseo 宿主。
[真机验证](../verification/pocket-image-0.1.9/summary.json)核对了选中原图与模型收到的
字节一致，当时没有验证独立接收端的历史图片显示。

网页端另有自动发布流程，每六小时跟随官方稳定版，固定源码提交、接入源码适配、
测试并发布网页包。历史重连补丁在官方修复后移除。兼容维护属于发布方，消费方
安装更新产物，不需要逐台给宿主打补丁。见 [网页发布说明](../../web-assets/README.md)。

## 这次核实的边界

Paseo 0.17.1/0.17.3 的 `AgentManager.recordSubmittedPrompt` 使用
`submittedPromptText` 保存共享用户消息，未保留输入图片和上传附件元数据。
发送端可使用自己的附件缓存，其他客户端和冷启动历史缺少对应数据。选图成功、
模型收到原图与跨端历史显示是三个不同的验收点。

Workbench 自己冻结了钉钉/TAPD 原件，因此可用官方插件时间线接口修复显示，
不需要修改或重启 Paseo。显示失败只修复回执，不再次派发模型任务。

## 已停止的宿主适配方案

v0.11.8 曾包含一个显式启用的、绑定原生源码散列的 Node 加载适配器；只在隔离环境
验证过，两台日常宿主均未启用，启动脚本和 Paseo 源码没有修改。
这条路线需要在官方升级后重新核对，不能作为正式的 Pocket 修复交付。

从 v0.11.9 起，它移到 `paseo-plugin/tests/fixtures/`，不进入插件发布包，普通界面
验收也不加载它。显式研究验证不能作为正式 Pocket 修复或真机验收的证据。
保留实验只是为了复核缺失数据发生在哪一层，不能添加到用户日常 `NODE_OPTIONS`。

## 正式修复要求

Pocket/Access Pocket 的跨端历史问题尚未交付正式修复。应优先让 Paseo 原生保存
可跨端读取的附件引用，并由所有客户端使用同一协议；上游合并后随正常升级生效。
若需要暂时维护发行适配，也必须在现有自动构建与回归流程内交付完整更新产物，
不能要求用户每次升级后手动打补丁或重新启用宿主加载器。

网页构建适配只覆盖使用该网页包的入口，不能因此宣称官方客户端和锁定官方资源的
Pocket APK 都已修复。源码结构或协议发生变化时，发布流程应阻止未通过的产物上线，
由维护方处理兼容性。

验收必须包含三张不同原图和一个普通附件；独立接收端不携带发送端 IndexedDB，
核对原件字节、大图、附件保存、刷新和桌面/窄屏显示，同时确认没有额外模型派发。
