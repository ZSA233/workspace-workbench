# v0.5.0

- Recover transient Codex capacity, rate-limit and connection failures across all
  ordinary sessions on the same Paseo service, including Workbench Workers and
  Reviewers. Sessions outside registered projects are included.
- Default to sending only `继续` in the original session. This mode needs no host
  patch. Configure the continuation text, retry interval, one-hour time budget or
  unlimited retries, and disable recovery globally or for individual sessions.
- Add a global session recovery page and composer status controls with countdowns,
  manual continuation, stop actions and the actual recovery method.
- Optionally prefer native empty-input recovery when the local compatibility
  bridge is installed. Fall back to continuation messages when native recovery
  is unavailable before dispatch. The bridge is an explicit local host patch for
  Paseo 0.11.0; plugin installation does not install it automatically.
- Preserve retry budgets across plugin reloads. Keep uncertain deliveries pending
  verification instead of resending them or switching recovery methods. Cancel
  queued recovery when user input, permissions, mode or task authorization changes.
- Pause Worker and Reviewer phase timeouts while awaiting recovery, preserve the
  review round and authorization, and discard results from failed review turns.

Validation: TypeScript checks and all 602 Node tests passed locally. Isolated
actual Paseo hosts verified default continuation, native recovery, fallback without
the native interface, cancellation and plugin reloads with a local Codex protocol
fixture. Playwright verified desktop settings, custom continuation text, manual
continuation and session controls without page errors. These checks did not call
a real Codex model. Native mobile UI remains unverified.

Recovery applies to new failures and does not wake historical failed or archived
sessions. Quota, authentication, context-limit and unexplained retry-limit errors
require user action. The message API still has a gap between the final idle check
and sending; neither recovery mode guarantees exactly-once tool execution.
