# 档案话题与原始材料

选定方案 C，并按用户要求减少界面说明文字。视觉基准：[精简稿](concept-c-refined.png)；生成方式与完整提示词见 [prompts.md](prompts.md)。

## 实施顺序

1. 保留扩展 ID、旧设置及旧协议兼容，主入口改为“话题”。增加独立的档案 v2 连接器；打开界面不注册新采集项目。
2. 话题列表支持搜索、关注群筛选、分页和展开。仅在界面可见时检查列表更新；原文、上下文与图片按操作读取。
3. 多话题选择固定到用户已看到的消息版本。展开新消息、列表刷新、图片晚到均不自动扩大已选范围。底部材料区按话题分组，单条原文与图片可独立移除。
4. 预览冻结原文、引用、所选有界上下文和附件原件；已有分析默认不选。发送复用宿主开发会话，保存同一请求回执；结果未知只查询、不自动重发。
5. 简单设置提供服务连接、既有资料库、关注群及服务已注册工具。逐群“仅建题”使用服务已有 collect/off 策略。DWS、模型、来源采集仍在 AI 助手服务管理。
6. 验证连接换代、越界材料、版本冲突、去重、部分附件未就绪、未知投递、窄屏与固定布局；运行类型检查、受影响 Node 测试及隔离 Paseo 实际宿主验证。

## 界面约定

- 控件短标签：话题、搜索话题、全部关注群、已选、分析、当前会话、带入会话。
- 选中底色、复选框、状态点、消息/图片图标和数量表达范围；原始正文完整可读，辅助说明移至 tooltip、预览或设置。
- 来源群只显示一次。原文与媒体不重复添加标题。材料区有独立滚动范围；通知占固定行，不在列表上方插入横幅。
- 图标按钮均有可访问名称、Web 悬浮提示与触屏可达区域。

## 接口边界

现有机器 API /v2/archive/ 已支持资料库、话题列表/详情/更多关联消息、消息上下文、原件、逐群策略及工具目录。沿用这些接口，不拉全群聊天、不触发模型排查或群回复。

第一版使用可见页轮询，后续可评估接入服务变化流。目录使用 part=directory，不读取运行历史。通用话题材料导出接口可进一步收敛跨客户端快照一致性；第一版由 Workbench 校验话题修订、消息版本、群范围并冻结原件。

## 验证目标

- 真实 AI 助手服务只读验证与隔离协议样本分开记录。
- 新旧扩展协议保持兼容，不修改历史候选、需求或用户源数据。
- 实际宿主验证仅使用隔离 Paseo home、项目注册表和服务样本；不重载用户插件。
