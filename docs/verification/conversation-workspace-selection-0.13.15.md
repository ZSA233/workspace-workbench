# 按会话恢复工作区选择

2026-11-28，用户要求同一项目中 A、B 两个会话分别记住最后选择的 Workspace。之前面板虽有会话身份，但传给选择存储的是主机＋项目导航键，因此两个会话共用最后一次选择。

新增选择键包含主机、项目和 PASEO 原生会话 ID；Tab 仍使用项目导航键。选择状态与初始化完成状态携带作用范围，切换时不会把上一会话的旧值交给当前解析器；旧选择回调只保存原作用范围，不改变当前选择或 Tab。旧版明确按会话保存的记录仍可读取，无法归属的项目共享记录保留但不借用。

纯函数验证主机／项目／会话隔离、旧会话记录继承、拒绝借用项目记录、项目 Tab 语义保留，以及旧工作区不可用时回退主工作区。原有选择优先级与其他模型逻辑继续回归。

实际隔离 PASEO 使用临时项目与真实 Git 工作区，界面检查通过 32 项、浏览器异常为零：分别为 A 选择统计工作区、为 B 选择白名单工作区，反复 A／B／A 切换均恢复各自选择；跨项目后返回仍正确；宿主设置 RPC 核对两份独立记录后，完整刷新浏览器清空模块内存，A、B 仍恢复正确。首次新会话没有继承 A 的选择，手动选中后可继续在关联弹窗确认当前工作区。

关联、标题开关、后台生成、取消、收件人、项目切换、深浅主题及 320／360／480／680px 面板继续验证。模型为 HTTP 夹具，原生会话、宿主设置与 Git 为实际隔离对象，不作为本地模型质量证据。验证不重载正常安装、不向正常项目注册表添加临时项目、不投递档案资料。

最后增加的主工作区回退规则由真实调用的选择解析器单测覆盖；目录正常识别的界面恢复流程不受该补充规则影响。没有独立记录的历史会话需要重新选择一次，不声称能从没有所属身份的旧记录还原全部历史。

最终 `make check` 通过版本一致性、TypeScript 与完整 1,052 项 Node 测试；`verify-live.mjs` 的实际隔离宿主、工作进程与卸载回收检查通过；发布 tag 检查和本地插件打包通过。
